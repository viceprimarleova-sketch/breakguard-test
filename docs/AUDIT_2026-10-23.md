# BreakGuard V0.1 — audit și corecții, 23 octombrie 2026

Am verificat două proiecte publice Shopify și exemplele oficiale de migrare.
Auditul a găsit o utilizare reală pe care scanerul o rata și două situații în
care remedierea veche producea GraphQL invalid. Corecțiile sunt pregătite pe
ramura de revizuire `fix/shopify-audit-safety`; versiunea distribuită pe GitHub nu a
fost modificată. Nu s-au trimis mesaje către dezvoltatori.

## Rezultatul pe proiecte publice

| Proiect și versiune verificată | Fișiere urmărite de Git | Înainte | După corecție |
| --- | ---: | --- | --- |
| Shopify/shopify_app — `68fd8e4931b2934b6d70950bf398c79310d7268a` | 286 | Nicio constatare | O utilizare ScriptTag pentru analiză manuală |
| Shopify/shopify-app-template-remix — `2d966b7bda76d0b4d9730538048e4242860659c2` | 53 | Nicio constatare | Nicio constatare |

Numărul de fișiere descrie proiectele, nu numărul de fișiere acoperite de cele
trei reguli. Scanarea aplică filtrele de extensie și context documentate.

Constatarea confirmată este apelul `scriptTagCreate(input: $input)` din
`lib/shopify_app/managers/script_tags_manager.rb`, linia 106. Acesta este codul
unei biblioteci publice Shopify; constatarea nu dovedește că un anumit magazin
sau dezvoltator folosește acea ramură la execuție.

Am comparat constatarea cu sursa. Referințele din răspunsurile de test nu au fost
numărate ca apeluri de creare. Ambele proiecte externe au rămas nemodificate,
cu stare Git curată. Proiectul Remix este un control fără potriviri pentru
regulile actuale, nu o certificare generală a compatibilității API.

## Probleme reproduse și soluții implementate

1. **Utilizare ScriptTag ratată în Ruby.** Regula veche căuta cuvântul `ScriptTag`
   doar în JavaScript/TypeScript. Regula corectată recunoaște forme uzuale de
   creare/actualizare GraphQL și REST în JS/TS, Ruby și fișiere GraphQL. Citirea,
   ștergerea, numele generice și căile de teste/fixtures sunt excluse din această
   regulă. Rezultatul rămâne o constatare pentru analiză manuală.

2. **Înlocuire incompletă a `priceRule`.** Pe structura publicată de Shopify,
   versiunea veche înlocuia numai prima linie și lăsa în urmă câmpurile și
   acoladele obiectului. Rezultatul nu putea fi parsat ca GraphQL valid.
   Corecția folosește intervalul exact al câmpului din arborele sintactic și
   înlocuiește întreaga selecție suportată cu `discountTitle` și `discountCode`.

3. **Eliminare care lăsa o selecție goală.** Dacă `lastIncompleteCheckout` era
   singurul câmp cerut sub `customer`, versiunea veche producea `customer { }`.
   Acum acel caz rămâne nemodificat și este marcat pentru intervenție manuală.
   Programul nu inventează un câmp înlocuitor; Shopify precizează că API-ul
   Customer Account nu oferă un asemenea înlocuitor.

Parserul distinge câmpurile executabile de comentarii, șiruri de text și
declarații de schemă. Editările păstrează textul din jur și terminatoarele de
linie Windows. Aliasurile, referințele eliminate la variabile/fragmente,
structurile de discount nesuportate și documentele invalide rămân manuale.

## Verificare efectuată

- Suita inițială: **12 teste trecute**, deși exemplele oficiale expuneau erorile.
- Suita după corecție: **39 de teste trecute**, rulate pe pachetul instalat
  separat într-un mediu Python 3.12 nou, cu importurile izolate de directorul
  sursei. Cele 27 de cazuri suplimentare verifică detecția și limitele editării.
- Instalarea pachetului și a dependenței `graphql-core` a reușit. Am comparat
  hashurile modulelor instalate cu sursele finale: coincid.
- CLI instalat: scanare → JSON → previzualizare fără modificări → aplicare →
  rescanare, verificat cu succes pe un exemplu controlat eligibil.
- Pe cele două exemple oficiale problematice: remedierea `priceRule` produce
  GraphQL valid; cazul care ar goli `customer` rămâne identic cu intrarea.
- `git diff --check` nu a semnalat probleme de spațiere.
- Configurațiile CI au fost ajustate pentru dependența nouă și exemple valide.
  Nu s-a executat încă o rulare GitHub Actions a acestei ramuri; Windows/macOS
  și celelalte versiuni Python nu au fost reverificate în această sesiune.

Datele și rezultatele înainte/după sunt în `audit-results-2026-10-23.json`.
Testele de regresie sunt în `tests/test_audit_regressions.py`.

## Limitele rezultatului

Acesta este un audit tehnic. Nu confirmă cererea comercială, timpul economisit
sau disponibilitatea de plată a unui dezvoltator Shopify. Nu am efectuat apeluri
la magazine și nu am cerut parole, cod privat ori acces la date comerciale.

Cele două reguli pentru câmpuri GraphQL acoperă numai documente executabile
standalone `.graphql`/`.gql`; nu acoperă acele câmpuri în șiruri JS/TS/Ruby.
Nu se stabilește automat versiunea API folosită. Validarea sintactică nu
înlocuiește validarea schemei Shopify ori testele aplicației. Codul care citește
răspunsul trebuie revizuit când forma răspunsului se schimbă.

## Următorul pas

Corecția este pregătită pentru revizuire și integrare în versiunea de test.
După integrare este necesară verificarea CI și apoi un test voluntar cu un
dezvoltator Shopify, într-un cadru care permite solicitări de feedback. Invitațiile
pe forumul unde contul este restricționat rămân oprite; nu se ocolește moderarea.
